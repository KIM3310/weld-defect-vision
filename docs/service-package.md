# Service Package - weld-defect-vision

This package defines the most practical service shape for this repository. It is public-safe: no price promises, financial projections, or buyer-specific contract assumptions are published here.

## Buyer and Wedge

- **Service lane:** Industrial inspection validation
- **Primary buyer:** Manufacturing quality teams, welding inspection groups, industrial AI, and edge deployment reviewers
- **Front-door offer:** Inspection validation workflow
- **Service outcome:** Turn image-model proof into human-reviewed validation, defect taxonomy, and edge-readiness review.

## Build and Polish Priorities

- Polish defect taxonomy and human review path
- Clarify approved image-data boundary
- Add validation report acceptance criteria

## Buyer-Ready Deliverables

- Image-data review
- Validation study
- Edge-readiness checklist

## Activation Path

1. Use the public demo, README, screenshots, and tests to establish proof.
2. Confirm the buyer workflow, data boundary, owner, and acceptance criteria.
3. Build only the smallest workflow needed to prove the service outcome.
4. Add cloud resources, accounts, storage, or paid integrations only after the workflow boundary is approved.

## Margin and Risk Controls

- Keep validation human-reviewed and add inference hosting only after data approval.
- Keep the first service scope narrow, repeatable, and evidence-led.
- Keep private financial planning outside the public repository.
- Keep logs, analytics, and reports free of private payloads unless explicit approval exists.

## Portfolio Signal

The portfolio should present this repository as **Inspection validation workflow** under the **Industrial inspection validation** lane, with proof links routed to the live demo or repository evidence.
